# RCP Lab

Локальная лаборатория эволюционного поиска Python-программ и самозарождающихся миров. Веб-интерфейс, история экспериментов и чат на русском языке; код кандидатов исполняется в изолированной песочнице.

## Два режима

**Лаборатория (`/`)**: цель → план → кандидаты → проверка регрессий → принятая версия → следующий шаг. Чат: **Обсудить** — разговор; **Поручить** — приоритет следующего шага; **Проверить** — фактическое выполнение программы. Есть пауза, история, восстановление и визуальный просмотр колонии. Ручной режим собственных тестов остаётся на `/classic`.

**Самозарождение (`/world`)**: модель сама создаёт первый исполнимый мир из короткого направления, без исходного кода мира и списка механик. После первого жизнеспособного результата исходное направление больше не передаётся в запросы развития. Модель получает текущие законы, состояние, наблюдения и выбранный ею следующий вопрос. Отдельный серверный цикл продолжает симуляцию, пока модель предлагает новые законы. На странице видны реальная проекция состояния, хроника, архив вариантов и абсолютный 24-часовой срок.

Подробнее: [режим миров и его ограничения](docs/seed-world.md), [визуализатор колонии](docs/colony-viewer.md).

Модель подключается через локальный llama.cpp API `http://127.0.0.1:8081/v1`, алиас **`rcp-coder`**. Проверенный профиль для миров — **Qwen3.8-27B, GGUF UD-Q4_K_M**, с частичным GPU-offload. [Файл, контрольная сумма и проверенная конфигурация](deploy/qwen38-world.md). Старые материалы по Gemma сохранены как предыдущий профиль. Веса, бинарные файлы, CUDA-библиотеки и персональные данные в Git не входят. После установки облачные API для генерации и исполнения не требуются.

## Границы эксперимента

Обычный автопилот создаёт модуль с `solve(data)`: JSON-объект на входе и выходе. Он сохраняет ответы уже принятых тестов. Режим миров позволяет менять законы, но сохраняет внешний договор передачи состояния и его проекции, безопасность и срок запуска. Внутренние сущности, память и правила задаёт модель, а не готовая симуляция.

Ни один режим не гарантирует непрерывного улучшения. Модель может ошибаться или застревать; новизна и движение не доказывают интеллект, сознание или рост сложности. Самозарождение не дообучает веса LLM. Принятые изменения — проверенные на исполнимость гипотезы, а не доказанно лучшие миры. Текст чата — интерпретация; фактические счётчики и результаты исполнения показываются отдельно.

Код кандидата запускается через bubblewrap и prlimit: отдельные namespaces, без сети и устройств GPU, ограниченная файловая система, до 256 МиБ адресного пространства, лимиты CPU/времени/вывода. Это исследовательская изоляция, не гарантия против всех атак на общее ядро. Используй отдельную непривилегированную VM/LXC, не передавай секреты или Docker socket.

## Запуск на Linux / Ubuntu 24.04

Требуются Python 3.12, venv, bubblewrap, util-linux, git и работающие пользовательские namespaces. Не запускай панель от root. В некоторых окружениях AppArmor или контейнерный профиль блокирует bubblewrap — сначала проверь тесты, а не отключай защиту целиком.

```sh
sudo apt-get install python3-venv bubblewrap util-linux git
git clone https://github.com/renosaza/RCP.git
cd RCP
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export RCP_DATA="$PWD/runtime"
export RCP_USERNAME=admin
read -rsp 'Пароль панели: ' RCP_PASSWORD; echo
export RCP_PASSWORD
mkdir -p "$RCP_DATA"
# Сначала запусти локальный llama-server с алиасом rcp-coder на порту 8081.
.venv/bin/uvicorn app:app --host 127.0.0.1 --port 8765 --workers 1
```

Открой `http://127.0.0.1:8765` или `http://127.0.0.1:8765/world`. Для LAN можно явно изменить адрес прослушивания, но не публикуй HTTP-порт в Интернет: Basic Auth без TLS не защищает пароль в недоверенной сети. Для удалённого доступа используй SSH-туннель либо отдельно настроенный HTTPS.

Примеры модели и systemd-панели — в `deploy/`. Пути к llama.cpp, весам и библиотекам должны соответствовать окружению. Мультимодальные проекторы не используются. Одновременно развивается один эксперимент; закрытие вкладки не останавливает серверный цикл.

## Проверки

```sh
export RCP_DATA="$(mktemp -d)"
export RCP_USERNAME=test-user
export RCP_PASSWORD=test-only-not-a-real-password
.venv/bin/python -B -m unittest test_lab test_autopilot test_chat test_shapes test_reliability_v2 test_worlds -v
```

84 теста покрывают прежнюю лабораторию и новый режим: песочницу, регрессии, приоритеты, запуск из чата, сохранение состояния, отсоединение исходной затравки из полного запроса, ограничения проекции и запрет работы после deadline. Им не нужна LLM, но нужен работающий bubblewrap. Тестовые программы мира — только фикстуры инфраструктуры, они никогда не используются как исходный мир настоящего эксперимента.

`tests/world-ui.test.cjs` выполняет восемь проверок страницы с подставленным API: обновление кадров, таймер, отсутствие самопроизвольных записей, сохранение черновика, безопасность вывода и адаптивность. Нужен доступный Playwright/Chromium; путь к уже установленному модулю можно передать через `PLAYWRIGHT_MODULE`. Проверка интерфейса с подставленными данными не заменяет запуск настоящей модели.

## Хранение и эксплуатация

`RCP_DATA` содержит приватные проекты, миры, переписку, код и результаты. Не коммить этот каталог. В лаборатории используется `missions`, в режиме миров — `worlds`. При перезапуске панели сохраняются намерение продолжать работу и исходный срок мира.

Обычный автопилот: до 18 000 символов кандидата, банк 80 тестов / 18 КБ, последние 20 версий и 5 подробных раундов. При приближении к пределу тестов поиск переходит к улучшению существующего кода; новые поручения не должны ошибочно считаться выполненными.

Миры: до 18 000 символов кандидата, 48 КБ состояния, проекция 1–160 узлов / до 600 связей; последние 128 метаданных вариантов и снимки принятых версий с полным кодом. При создании фиксируется окно до 24 часов. Пауза или перезапуск его не продлевают. Ошибки кандидатов не удаляют рабочий мир; авария процесса, нехватка диска или отключение сервера могут прервать выполнение. Это конечная экспериментальная среда, не обещание бесконечного усложнения.
